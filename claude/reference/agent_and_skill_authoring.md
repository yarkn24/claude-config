# Agent and Skill Authoring

Read before writing a dispatch that needs a skill, an agent definition, or a new skill.

- **A subagent inherits no skills, and a missing skill fails silently.** Supply it: a fixed dependency goes in that agent's `skills:` frontmatter, which injects the full skill text at startup, not just the description; a situational one is named in the dispatch prompt and loads only if `Skill` is in that agent's `tools` list. Omitting `tools` inherits it; an explicit list without it blocks on-demand loading entirely. A skill marked `disable-model-invocation: true` cannot be preloaded at all, and is skipped with a debug-log warning only.
- **A saved agent definition sets `model` explicitly, and sets `skills` when its job has a real skill dependency.** The dispatch-level hook reads the Agent call's `model` param and never sees a definition file. An agent `.md` with no `model:` line resolves down through `CLAUDE_CODE_SUBAGENT_MODEL` (if set) to the main conversation's model, making the tier an accident of whichever session dispatched it. `inherit` is a choice, not a default, and needs the same stated reason. Add `skills` only after confirming the agent's own job performs the skill-covered action; a topical mention is not a dependency, and a preloaded skill is injected in full on every dispatch.
- **A subagent never installs a skill live.** It reports the gap, or drafts the skill to `~/.claude/skills_staging/<name>/SKILL.md`, which sits outside every root the loader reads and stays inert until promoted. The report carries that path and one line on the gap, never the draft's body. MAIN reads the staged file, puts it through the same fresh-Opus review as any other system addition, decides global or project scope, then moves the directory into the live `skills/`. Never stage inside a `skills/` root: the loader reads only a root's immediate subdirectories, so depth is the only thing hiding a draft and an underscore prefix buys nothing.
